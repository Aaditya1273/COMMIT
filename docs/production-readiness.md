**PARTIAL** = works, with a stated gap; **INCONCLUSIVE** = cannot be tested in the
available environment; **NOT TESTED** = not exercised. No readiness percentage is given,
because none has been defined that could be computed honestly.

## Security audit

Source review of `commit/` and `scripts/`, with the fix for each finding:

| Finding (before 1.0.0-rc.1) | Fix |
|---|---|
| `{out}` substituted unquoted into shell commands: a crafted `--out` could execute commands | values substituted into plan commands are POSIX-quoted; regression test |
| child output buffered without limit (memory exhaustion) | streamed to disk with a byte cap; truncation recorded |
| detached children survived an interrupt; temp workspaces leaked | live-child registry, process-group termination, interrupt cleanup |
| non-atomic artifact writes (torn JSON after a crash) | atomic temp + fsync + rename everywhere |
| step logs could carry credentials into public evidence | redaction before hashing; repository credential scan |
| test fixtures contained credential-shaped strings that bootstrap would install into result repositories | fixtures assembled at run time |
| equivalents register entries never re-validated | schema + staleness check against the current source |
| bootstrap overwrote existing files silently | conflict detection before any write; `--force` backs up |

JSON is parsed with `JSON.parse` only (no YAML, no `eval`); campaign modules are loaded
with `import()` by design — a campaign module is code the verifier wrote, like a plan.
No CVE scoring is claimed.

## Remaining risks

- No BAND run has happened: seat behaviour, handoff quality, token costs and autonomy
  are unmeasured until it does.
- Container and offline behaviour of any service are unverified on this machine.
- The verifier's independence is detected after the fact, not enforced by the OS.
- The calibration target was written by the same author as its verification layers;
  the mutation score measures the verifier against that target, not the band's work.
